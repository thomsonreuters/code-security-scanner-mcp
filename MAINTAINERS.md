# Maintainers

Maintainers review and merge pull requests, triage issues, cut releases and keep this project welcoming. Anyone can
contribute; you don't need to be a maintainer or work at Thomson Reuters to open an issue or a pull request.

Every pull request is reviewed by at least one maintainer (see
[CONTRIBUTING.md](CONTRIBUTING.md#how-pull-requests-are-reviewed)). `.github/CODEOWNERS` requests that review
automatically.

## What maintainers do

- **Triage.** One maintainer is on triage each week. They label new issues, ask for missing details, and point newcomers
  to issues labelled `good first issue` or `help wanted`.
- **Review.** Maintainers review pull requests from everyone, maintainers included, and help contributors get their
  change over the line rather than only judging it.
- **Release.** Maintainers tag releases. Publishing to PyPI goes through the release workflow and needs a second
  maintainer's approval.
- **Security.** Maintainers handle private vulnerability reports as described in [SECURITY.md](SECURITY.md).

## Becoming a maintainer

We want maintainers from outside Thomson Reuters. Contributors who have made several substantial, well-tested
contributions and helped others in issues or reviews can be invited by an existing maintainer. The current maintainers
agree by consensus in a pull request that adds the new name to this file. You can also ask: open an issue and say what
you'd like to help with.

Maintainers who step back move to the list below, so their work stays credited.
